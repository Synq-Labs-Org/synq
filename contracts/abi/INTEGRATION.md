# Synq contract integration (Safe v1.4.1 group accounts)

ABIs in this directory are generated by `forge build --root contracts` and `python3 contracts/export-abi.py`. `SafeL2.json` and `SafeProxyFactory.json` come from the vendored official Safe v1.4.1 source. `LocalTestToken.json` is a local-only fixture.

## Deployment topology

One transaction deploys `SynqGroupFactory(safeL2Singleton, safeProxyFactory, compatibilityFallbackHandler)`. Its constructor deploys `MandateRegistry`, `ExecutionModule(registry)` and `SynqSafeModuleSetup`; read their addresses from `factory.registry()`, `factory.module()` and `factory.moduleSetup()`. All three contracts are singletons that serve every group. They are non-upgradeable.

## Group lifecycle

1. `factory.createGroup(address[] owners, uint256 threshold, bytes32 salt) returns (bytes32 groupId, address account)`.
   - `groupId = keccak256(abi.encode(chainId, factory, msg.sender, salt))`. Use `factory.computeGroupId(creator, salt)` to get it ahead of time. Because the id includes the creator, it cannot be front-run.
   - The account is a SafeProxy over SafeL2 (`createProxyWithNonce`, `saltNonce = uint256(groupId)`). It is created with CompatibilityFallbackHandler, and `ExecutionModule` is enabled during `Safe.setup`.
   - The registry binds `groupId <-> account` and sets the module allowed to record spend.
2. Owner-quorum Safe transactions (`execTransaction`, CALL, 2-of-3 signatures) configure everything else. They can be batched through MultiSendCallOnly via DELEGATECALL from `execTransaction`, which is the standard Safe pattern.
   - `module.setExecutor(executor, true)`
   - `registry.configureMandate(mandateId, MandateConfig)`
   - Optional: `registry.supersedeMandate(...)`, `registry.revokeMandate(...)`, `module.pause()` / `module.unpause()`, `module.cancelNonce(nonce)`, `registry.setModule(newModule)`.
3. The executor calls `module.execute(grant, data, signatures)`.

The governance functions authenticate `msg.sender == account`, so they succeed only when sent from the Safe itself.

## MandateConfig

Tuple order: `(bytes32 mandateHash, address token, uint256 maxTokenPerAction, uint256 maxNativePerAction, uint256 cumulativeTokenCap, uint256 cumulativeNativeCap, uint256 validAfter, uint256 validUntil, address[] callTargets, bytes4[] callSelectors, address[] recipients)`.

- An ERC20 transfer needs `(token, 0xa9059cbb)` in the call allowlist. A native transfer to R needs `(R, 0x00000000)`. Every recipient must be in `recipients`.
- Validation: `validAfter < validUntil` and `validUntil > now`. Lists must be non-empty and hold at most 32 entries each. If `token == 0`, the token caps must be 0. The account, registry, factory, current module and zero address are forbidden as token, call target or recipient. The token contract cannot be a recipient.
- Versions: `configureMandate` creates v1. `supersedeMandate(id, current + 1, config, securitySensitive)` creates the next version. The token denomination cannot change. Revocation is terminal: a revoked id can never be configured or superseded again.
- Grant validity per version: a grant for version v is valid if `minValidVersion <= v <= currentVersion`. A security-sensitive supersession sets `minValidVersion` to the new version.
- Caps: the per-action caps and window come from the granted version. Cumulative spend is per (account, mandateId) and persists across versions and modules. For each spent dimension, it is capped by the lower of the granted version's cap and the current version's cap.

## ExecutionGrant (EIP-712)

Domain: `EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)` with `name = "SynqExecutionModule"`, `version = "1"`, `chainId` = the current chain and `verifyingContract` = the ExecutionModule address.

Type string (exact):

```
ExecutionGrant(bytes32 groupId,address account,bytes32 mandateId,uint256 mandateVersion,address executor,bytes32 pluginId,uint256 chainId,address target,bytes4 selector,bytes32 calldataHash,address token,uint256 maxInputAmount,uint256 nativeValue,uint256 minOutputAmount,address recipient,uint256 validAfter,uint256 validUntil,uint256 nonce,bytes32 intentHash)
```

`module.hashGrant(grant)` returns the digest. `module.grantStructHash(grant)` and `module.domainSeparator()` return its parts.

Supported action shapes:

| Action | target | selector | data | token | maxInputAmount | nativeValue | recipient | minOutputAmount |
|---|---|---|---|---|---|---|---|---|
| ERC20 transfer | token | `0xa9059cbb` | `transfer(recipient, amount)`, exactly 68 bytes | token | amount (>0) | 0 | decoded recipient | <= amount |
| Native transfer | recipient | `0x00000000` | empty | 0 | 0 | value (>0) | = target | <= value |

Any other selector reverts with `UnsupportedAction`. The module checks `keccak256(data) == calldataHash`. It requires the actual balance changes to be exact: the account is debited by exactly the amount and the recipient is credited by exactly the amount. This rejects fee, rebasing and false-return tokens. The validity window is `validAfter <= block.timestamp < validUntil`. Each nonce and each intentHash can execute only once per (module, account).

## Signatures

`signatures` uses the standard Safe v1.4.1 format. Signatures must be ordered by owner address ascending, and at least `threshold` are required. Each 65-byte entry `{r}{s}{v}` is one of:

- ECDSA over the grant digest, with v in {27, 28};
- eth_sign over `"\x19Ethereum Signed Message:\n32" || digest`, with v + 4;
- approved hash, with `r = owner` and `v = 1`, after the owner calls `safe.approveHash(digest)`;
- contract-owner signature, with `r = owner`, `s = offset` and `v = 0` plus dynamic data. The owner validates the 66-byte EIP-712 preimage `0x1901 || domainSeparator || structHash`. For a nested Safe owner, sign `getMessageHashForSafe(ownerSafe, preimage)`.

Signatures with `s > secp256k1n/2` are rejected with `MalleableSignature(index)`.

The module checks signatures by calling `account.checkSignatures(digest, preimage, signatures)` on the group Safe. Owner identity therefore always comes from the Safe's current owner set and threshold.

## Events

```solidity
// SynqGroupFactory
event GroupCreated(bytes32 indexed groupId, address indexed account, address[] owners, uint256 threshold, address module, address registry, address indexed creator, bytes32 salt);
// MandateRegistry
event GroupBound(bytes32 indexed groupId, address indexed account, address indexed module);
event GroupModuleChanged(bytes32 indexed groupId, address indexed account, address previousModule, address newModule);
event MandateConfigured(bytes32 indexed groupId, bytes32 indexed mandateId, uint256 indexed version, address account, bytes32 mandateHash, address token, uint256 maxTokenPerAction, uint256 maxNativePerAction, uint256 cumulativeTokenCap, uint256 cumulativeNativeCap, uint256 validAfter, uint256 validUntil, address[] callTargets, bytes4[] callSelectors, address[] recipients);
event MandateSuperseded(bytes32 indexed groupId, bytes32 indexed mandateId, uint256 indexed newVersion, address account, uint256 previousVersion, bool securitySensitive, uint256 minValidVersion);
event MandateRevoked(bytes32 indexed groupId, bytes32 indexed mandateId, uint256 indexed version, address account);
event SpendRecorded(bytes32 indexed groupId, bytes32 indexed mandateId, uint256 indexed version, address account, address module, uint256 tokenAmount, uint256 nativeAmount, uint256 spentToken, uint256 spentNative);
// ExecutionModule
event ExecutorSet(bytes32 indexed groupId, address indexed account, address indexed executor, bool allowed);
event Paused(bytes32 indexed groupId, address indexed account);
event Unpaused(bytes32 indexed groupId, address indexed account);
event NonceCancelled(bytes32 indexed groupId, address indexed account, uint256 indexed nonce);
event GrantExecuted(bytes32 indexed groupId, bytes32 indexed intentHash, bytes32 indexed mandateId, uint256 mandateVersion, address account, address executor, bytes32 pluginId, uint256 chainId, uint256 nonce, bytes32 grantHash, address target, bytes4 selector, bytes32 calldataHash, address token, address recipient, uint256 tokenAmount, uint256 nativeValue, uint256 outputAmount);
```

`MandateConfigured` is emitted for every version. `MandateSuperseded` is also emitted on every supersession. The Safe itself emits `SafeSetup`, `EnabledModule`, `ExecutionSuccess`, `ExecutionFromModuleSuccess`, `AddedOwner`, `RemovedOwner` and `ChangedThreshold`. SafeL2 also emits `SafeMultiSigTransaction` and `SafeModuleTransaction`.

- Module: `AccountNotRegistered`, `InvalidExecutor`, `AlreadyPaused`, `NotPaused`, `Reentrancy`, `ExecutionPaused(address)`, `InvalidSignatures`, `MalleableSignature(uint256)`, `WrongChain(uint256,uint256)`, `UnauthorizedExecutor(address)`, `GroupMismatch`, `ModuleNotAuthorized`, `ModuleNotEnabled`, `GrantNotYetValid`, `GrantExpired`, `InvalidIntent`, `NonceAlreadyUsed(uint256)`, `IntentAlreadyExecuted(bytes32)`, `CalldataMismatch`, `SelectorMismatch`, `ProtectedAddress(address)`, `UnsupportedAction(bytes4)`, `InvalidActionShape`, `ExecutionFailed`, `BalanceDeltaMismatch`, `InsufficientOutput`.
